# Glossary

The words Rootnote uses, and what they mean in this guide.

## Terms

| Term | Meaning |
|---|---|
| Additional details | The part of a finding where text blocks and screenshots alternate in reading order. |
| Check & export | The view that lists reminders before export and makes the Word, Markdown, CSV and PDF output. |
| CVSS 3.1 Base | A standard score for a vulnerability, built from metrics you choose. Rootnote calculates the Base vector and score only. |
| CWE | Common Weakness Enumeration: a standard number for the kind of weakness, for example CWE-79 for cross-site scripting. |
| Engagement | One piece of work for one client, for example a web application test. |
| Engagement ID | Your reference for the engagement. Finding IDs are built from it. |
| Engagement folders | An optional folder layout, one folder per customer and engagement, that Rootnote can list and save into. |
| Engagement status | Where the report stands: Draft, In review, Delivered or Retest due. You set it; nothing changes it automatically. |
| Finding | One issue in the report, with its rating, facts and text. |
| Finding library | A separate file of reusable findings, opened and saved like a project. |
| Finding status | Where the issue stands: Open, Fixed, Partly fixed, Risk accepted or False positive. |
| Live page | The approximate preview beside the editor on a wide window, showing the page you are editing. |
| Project file | The `.rootnote.json` file that holds the whole report. Your working copy. |
| Prompt | Text in double brackets, such as `[[affected endpoint]]`, that you must replace with your own findings. |
| Recovery draft | An optional, unencrypted copy of the open project kept in this browser. Not a backup. |
| Sample | The example report built into Rootnote, for a fictional client with synthetic evidence. |
| Unscored | A finding without a rating, or without a CVSS vector when the report shows CVSS scores. Different from a score of zero. |
